The project uses Next.js because it provides a simple path to scale this prototype into a larger full-stack application if needed. For styling, I chose Tailwind CSS because it makes it easy to prototype quickly while keeping the UI consistent and the code straightforward to review. The codebase follows my preferred feature-based organization, where each major capability lives in its own module. This keeps the scope of each feature localized and makes it easier to introduce supporting patterns such as context providers, services, or feature-specific state at either the application root or page level.

For this assignment, most of the behavior lives inside src/modules/sticky-note, which acts as the domain layer for the sticky note board. That module contains the note types, presentation components, board state management, and interaction logic, which keeps the rest of the app relatively thin. One example is the custom dragElement utility: instead of relying on the browser’s default draggable API, I implemented a lightweight drag system to achieve a smoother and more predictable interaction model. The tradeoff is that this approach also requires rebuilding parts of the drop behavior manually, which I kept intentionally simple for the scope of the assignment.

For note updates, I used an uncontrolled-style interaction model to avoid re-rendering React components on every mouse movement. During drag and resize interactions, the note position and dimensions are updated through CSS variables for immediate visual feedback, and the React state is only committed once the interaction is complete. I used the same approach for resizing and text updates so the board remains responsive while keeping React state as the source of truth at the end of each action.
